# Changelog

What changed between versions, for users of the library and the CLI. Breaking changes are marked **breaking**.

## Unreleased

### Security

- Every walk of a value is bounded by the call that makes it: its text (a text mark, label, aria description, group key, sort key or format of an array), its JSON (a stack's group key, `VegaLiteToVega`'s output), a deep or relational comparison, an elementwise interpolation (C1, C13). A value whose arrays share their parts (a few expressions make one standing for 10^8 elements) was walked whole, unmetered: a 2 KB specification was OOM-killed under `WithMemoryLimit(256 MiB)`, and a scale domain of two such arrays ran 20 s past a 2 s timeout. Each value visited is now a step of the call's work and the text built is charged to its memory, so the render ends with `ErrLimit` or the deadline. Comparing an array with itself is no longer a walk at all. ([ADR 0018](docs/adr/0018-value-walks-bounded-by-the-call.md))
- An ordinal, band or point scale finds a domain value that is an array or an object in constant time, by identity, as d3's InternMap does; 64,000 such values took 14 s (C25).
- `vlSelectionResolve` keys its ids as d3's InternSet does, by identity, and never makes their text (C102).
- `timeSequence` and `utcSequence` charge each date to the expression's budget as the array grows (C106): four million milliseconds under a 1 MiB budget built 160 MB of dates before the charge failed, and now stop at the budget.

### Fidelity

- **breaking (fewer successes):** a value nested past 1,024 levels fails with `ErrLimit` wherever it is printed, compared or interpolated, as it already did in an expression's string (C103). It printed as `""` in a text mark, compared unequal, and interpolated to its end value.
- A parsed JSON object (a specification, loaded data) and every object the engine builds list their keys in JavaScript's order, array indexes first and ascending (C154): `{"b":1,"1":2}` is written `{"1":2,"b":1}` by `aster compile` and `VegaLiteToVega`, as `JSON.stringify(JSON.parse(…))` writes it.
- A lone surrogate escape in JSON (`"\ud83d"`) is kept as the code unit JSON.parse keeps, as an expression's string holds one, and written as its `\ud83d` escape in JSON output, as `JSON.stringify` writes it; text output (SVG, and with it PNG and PDF) and text measurement read each lone surrogate as one U+FFFD, as JavaScript's UTF-8 does: an expression's lone surrogate printed as three (C155).
- Decimal text converts to the number JSON.parse gives in every reading: `Number()`, an expression's literal, `parseFloat`, `parseInt` in radix 10, CSV fields, path data, colours and time parsing. A literal of more than 800 digits could read as 0 (C99).
- Text is lower- and upper-cased as JavaScript does (C90): `"type": "quantİtative"`, the scheme `"vİridis"` and the colour `"Whİte"` are no longer recognised, as upstream does not recognise them; the same for interpolator, projection and transform names, time-locale names, and the capitalised legend caption and axis configuration key. A month or day name in time parsing matches case-insensitively as a JavaScript regular expression does (not the Kelvin sign for `k`).
- A JSON syntax error names the character found (decoded), or the byte in hex when the text is not UTF-8 there: a byte-order mark was reported as `'ï'`.
- The expression language's functions answer as upstream's do, checked by a new differential of about 14,000 expressions against upstream in node (every function with edge arguments, the order it evaluates them in, the members values inherit; [testing.md](docs/testing.md)):
  - `split(str, regexp, limit)` stops at `limit` pieces, captures included, and skips an empty match only where a piece begins (C38): `split('abc', regexp(''), 2)` is `["a", "b"]`, not `["a", "bc"]`, and `split('a,b,,c', /,*/, 3)` is `["a", "b", "c"]`.
  - The string literal `'then'` is a string (C98); it read as a signal reference. A string literal naming a member of `Object.prototype` (`'toString'`) is still read as an identifier, as upstream's parser reads it.
  - Arguments are evaluated when and in the order upstream's generated code evaluates them (C100): `clamp(v, lo, hi)` evaluates `lo`, `hi`, then `v`; `upper`, `lower`, `trim`, `length` and the date getters (`year`, `utcmonth`, `time`, …) never evaluate (or compile) arguments past their first; `test(pattern, s)` fails on an invalid pattern before it evaluates `s`; the event functions (`x()`, `item()`, …) fail where there is no event before evaluating their arguments. The order shows in `warn()`'s output and in side-effecting functions.
  - `clampRange`, `flush`, `bandspace`, `densityUniform` and `cumulativeUniform` compare their arguments as given (C101): `flush(['10','9'], 9.1, …)` compares the strings, `clampRange` returns `[min, max]` as given when the span exceeds them, and `bandspace('0')` is 1.
  - `parseInt` in a radix other than 10 or a power of two accumulates as V8 does, so values past 2^53 match it to the last bit (C104).
  - Members a value inherits read as functions (C156): `datum.values.map`, `'brighter' in rgb('red')`, `datum.date.getTime` and `datum.x.toFixed` are functions, as upstream's; they print as native code, and an expression still cannot call them. `merge` of a colour copies its methods, as a for-in loop does. Only `rgb()`, `hsl()`, `lab()` and `hcl()` make colours: an object of the same shape prints as `[object Object]`.
  - `pan*` and `zoom*` read a string or an array-like domain as upstream does; `pluck` splits a field name that is not a string as upstream's `field` does, and fails on a malformed path; `indata` takes two arguments, and its field must be a string literal; `btoa()` with no argument fails; `timeFormat`/`utcFormat` take a date or a pattern as a multi-format specifier (its defaults), as any object.
- **breaking (fewer successes):** an identifier may hold only the characters upstream's parser accepts, tested per UTF-16 code unit against its own tables (C105): a character outside the Basic Multilingual Plane (`datum.𝑥`) or one added to Unicode since those tables is a parse error, as upstream's.

- **breaking (fewer successes):** more Vega-Lite input that upstream's compiler rejects fails as upstream's does, with its message ([ADR 0013](docs/adr/0013-invalid-input-fails-where-upstream-throws.md)), found by the nightly type-confusion differential (seeds 20741 and 20742):
  - a scale `domain` naming a member of `Object.prototype` (`"constructor"`, `"toString"`, `"__proto__"`, …), which upstream's deduplication reads as already seen, so hashing the empty domain fails;
  - under 6.4, an encoding that is both a value and a field (a layer's `{"value": …}` merged into a child's field definition), whose aria description upstream fails to build;
  - under 5.8, a mark whose invalid-value filter is left with no field to filter;
  - views whose shared scale merges a `range` of `null` with another range, whose `step` upstream reads.
- Where upstream compiles such input, the output now matches it: under 5.8 a tick with `config.tick.bandSize: null` has no size channel; a binned position on a channel with `scale: null` names no scale; an empty expression in a tooltip built from the encoding is written empty, not as `undefined`; and a scale `type` that a `datum` encoding keeps without checking it (`{}`, `[]`, a number, a boolean) is written as given, not as its text (`"[object Object]"`, `"1"`).

## v0.2.0 (2026-10-14)

### Security

- A regular expression made from a string (`regexp()`, `test()` and the other string functions given a string pattern) pays the call's ledger for the two copies of its source it makes, the escaped source and the cache key, before it makes them. Each is as long as the source, which may be 1 MiB, and was bounded by that alone; a ledger without room for them now refuses the pattern with `ErrLimit` before they exist, also when the pattern is already cached. Both are given back once the pattern is built.
- SVG output escapes a mark's `x`, `y` (and with them the `transform` attribute) when they are strings rather than numbers. Before, such a string, from the spec or from **data** (a Vega `{"field": …}`, a Vega-Lite channel with `"scale": null`), was written into `transform="translate(…)"` unescaped, so a data value could add markup, such as a `<script>` element, to SVG that a page inlines; PNG and PDF output, made from that SVG, could carry it too. The output is now upstream Vega's, escaped. Charts whose positions are numbers are unchanged. The SVG writer now accepts raw markup only as constants, and tests check that its output parses back to exactly the elements and attributes it wrote.
- A hostile font no longer amplifies memory when a PDF embeds it: a table directory naming one table hundreds of times (a 418 KB font gave a 132 MB font program) is read as every reader reads it, the first record of a tag being the table, and a font whose tables overlap, or whose glyphs overlap in `glyf` (a 140 KB font gave `SubsetFont` a 216 MB subset), is not cut or subset: its text is drawn as outlines, and `SubsetFont` returns an error saying why.
- `SVGToPDF` joins a `<text>`'s character data in linear time: text in many CDATA sections took a minute for 6 MB.
- The PDF writer decodes each distinct image once per conversion (by its href, and by its bytes when two hrefs carry the same image), writes it once however many marks draw it, and charges the pixels it decodes and the planes and streams made from them to the call's ledger before making them: a 4096² PNG drawn by 8 rows reached about 140 MiB under `WithMemoryLimit(64 MiB)` with no error, and now fails with `ErrLimit`. An 8-bit RGBA image is no longer copied before it is written.
- The PDF writer's per-render caches (glyph outlines, painted colour glyphs, forms, ExtGStates) and its content stream are bounded by bytes or charged to the call's ledger, and a font program it cuts out of a collection or a system font is charged before it is made and kept within 64 MiB per converter. A converter with `WithSystemFonts` keeps at most 64 system font faces loaded, however many families specifications name.
- **Security:** `HTTPLoader`'s private-network check covers every path a caller's `*http.Transport` dials (C41). A Transport that set only `DialTLSContext` (or only the deprecated `Dial` or `DialTLS`) had its plain-http connections made by net/http's zero Dialer, unchecked, so a name resolving to loopback was reached. Its dial functions are now wrapped (the deprecated ones as their context forms), and the guarded dialer makes any connection it leaves to net/http.
- **Security:** a refused connection's error no longer names the internal address a host resolved to (C88); it wraps the new `ErrPrivateAddress` text, "the host is a private or loopback address". A body over a loader's cap names the cap that was reached: `HTTPLoader.MaxResponseBytes`, `FileLoader.MaxBytes`, what is left of the call's load budget, or the 32 MiB of one image.

### Breaking

Each of these can change what an existing program gets: output, an error where there was none, or a refused option.

- **breaking:** a render fails when upstream Vega would log a problem and draw without it. This covers a data URL the Loader refuses or fails to load (including every URL under the default `DenyLoader`), loaded data that does not parse, an image that cannot be loaded or decoded, and an exception an expression or operator raises during evaluation. Before, these rendered a chart missing the data or the image, with a nil error. Data and image failures are an `*aster.LoadError` (`Resource`, `URL`, `Err`). ([ADR 0006](docs/adr/0006-errors-reach-the-caller.md))
- **breaking:** a family you register faces for (`WithFont`, `WithFontFace`, `WithFontInstance`) is made of your faces alone, as a CSS `@font-face` family is. Registering "Liberation Sans" or "Arial" now replaces the embedded font of that name; before, the embedded face won. Of faces of equal fit, the last registered now wins; before, the first did. Both are what the documentation said. ([ADR 0009](docs/adr/0009-caller-chooses-fonts.md))
- **breaking:** `New` loads the fonts given with `WithFont`, `WithFontFace` and `WithFontInstance` and fails for one that does not load. Before, the first render that needed text failed, and every render after it.
- **breaking:** the data-row bound (`WithMemoryLimit(n)` gives n/512 rows) bounds the rows alive. Each row is held by the operator that made it, replaced when that operator runs again (C13). Before, a filter credited the rows it dropped (ten filters dropping 900 rows paid for 9,000 rows elsewhere), the rows of an `aggregate`, a derived data set, a prefacet's cells, `nest` and `treelinks`, `modify()` and trigger inserts, `setdata()` and a Load from a signal were never counted, and a transform that ran again was counted twice (a `sequence` rerun from 600 to 601 rows failed as 1,201). A chart whose rows were not all counted can now fail with `ErrLimit` near the bound; the defaults are far above the corpus. The limit error is the budget's own ("data rows 1500 exceeds the limit of 1000"). ([ADR 0012](docs/adr/0012-rows-held-by-their-maker.md))
- **breaking:** `New` refuses options it used to replace silently (C74–C79): a `WithDefaultFontFamily`, `WithDefaultSerifFamily` or `WithDefaultMonospaceFamily` family with no font, a negative `WithFontFace` index, a nil pointer as the Loader (it panicked at first use), and `WithTimezone("Local")`, which made output depend on the host. `WithVegaLiteVersion` accepts the full version `AvailableVersions` reports (`"6.4.3"`, `"5.8.0"`); `AvailableVersions`' error, always nil, is documented as kept for compatibility (C106).
- **breaking (fewer successes):** an image over the per-image limit fails `VegaToSVG` with `ErrLimit` when it is read for the size of a mark that has none, as it fails PNG and PDF (C34); it vanished from the SVG with no error. A limit reached by any image always fails the call.
- **breaking:** a bound reached inside an expression ends the render with `ErrLimit` (or the deadline's error), never a JavaScript exception a `WithErrorHandler` could let go (C43): a string past 16,777,216 code units, a regular expression search out of steps (with `test` and the `g`/`y` flags too, where it read as `false`, C97) or a pattern past goecma262's limits, a `timeSequence` past 4,194,304 dates, a value nested past 1,024 levels, and the deadline. A string past V8's own limit (`pad(x, 1e12)`) stays the `RangeError` upstream throws. A `*budget.Stop` or an operator's own failure raised from inside an expression is no longer reported as an "internal error" the dataflow logged and went past.
- **breaking:** a projection `clipAngle` whose magnitude reaches 2^50 radians (about 6.4e16 degrees), infinity included, fails the render with `ErrLimit`. Upstream never finishes drawing a sphere or a clipped polygon with it; with 1e18 the render looped for ever and `Close` blocked behind it.
- **breaking:** a `collide` or `link` force's `iterations` over 1,000 fails with `ErrLimit` naming the number, instead of running 1,000; a fractional count runs as `k < iterations` does (1.5 runs twice). Limit errors name the number the specification asked for (`sequence length 1e+300`), not a clamped or wrapped int.
- **breaking:** a window operation that reads a row the frame does not have (`first_value` or `last_value` of an empty frame, `nth_value` at a NaN end, `lag` with a negative offset past the end) raises upstream's `TypeError: Cannot read properties of undefined`, which reaches `WithErrorHandler` as other operator exceptions do; it gave `undefined` or `null`. A window's `RangeError: Invalid array length` and the `TypeError` of a sort reading undefined carry their names, as upstream's messages do.
- **breaking:** a `config.locale` member past a bound far above any real locale fails the render with `ErrLimit` (number: 16 bytes for the decimal, thousands separator, minus sign and each numeral, 64 for currency, percent and NaN; time: 256-byte patterns expanding to 4 KiB at most, 128-byte names, 64 per list). A 2 KB locale could make each label megabytes long: a 67 MB SVG at 1.2 GB of memory with no error. Label text is now charged to the call's ledger, and the format memos are bounded by bytes ([docs/limits.md](docs/limits.md)).
- **breaking:** an axis or legend that would list more than 100,000 ticks or entries fails with `ErrLimit` before listing them, a `tickCount` with a `tickMinStep` included (it ran for seconds, past the timeout, at `tickCount: 1e9`). Time ticks past the bound (every 2 minutes over 95 years), and a scheme sampled for more than 1,048,576 colours, fail with `ErrLimit`; both were drawn empty, silently.
- **breaking (output):** PNG (SVG input): every SVG 1.1 filter primitive is drawn, as resvg draws it. `feImage`, `feTile`, `feMorphology`, `feConvolveMatrix`, `feDisplacementMap`, `feTurbulence`, `feDiffuseLighting` and `feSpecularLighting` gave a transparent result, so an element whose filter ended in one vanished; it is now drawn. An `feConvolveMatrix` kernel of more than 65,536 taps fails with `ErrLimit`, an `feImage` href is fetched through the Loader (a refused one is a `*LoadError`, as an `<image>`'s is), and a `<use>`'s clip, mask and filter move with its `x` and `y`. Details under Fidelity and Bounds.
- **breaking (output):** PNG (SVG input): filters follow W3C Filter Effects Module Level 1 where resvg departs from it ([ADR 0015](docs/adr/0015-filters-follow-the-specification.md); each change is in [api.md](docs/api.md#svg-input) with the specification's text, and asserted by a test). A PNG of SVG that relies on resvg's behaviour can change; Vega's output has no filters, so charts do not.
  - `feDisplacementMap` moves a pixel by `scale` times the map's distance from .5, once (it was `scale` squared), reads the map non-premultiplied, leaves `in` in its own colour space, and under `primitiveUnits="objectBoundingBox"` scales x by the box's width and y by its height (both were the mean of its sides).
  - `feTile` repeats its input's whole sub-region, from its corner, transparent where it lies outside the filter region (the tile was cut to the region, and one wholly outside failed the filter); the result keeps its input's colour space (it was tagged sRGB).
  - `feTurbulence` uses the specification's gradients (a gradient drawn again while zero or longer than 1, SVG 1.1's code normalizing every one), stitches over the primitive's sub-region (the filter region in pixels and each pixel's index were used), takes the seed whole past 32 bits, and reads a `numOctaves` that is not a whole number as 1 (it was rounded). Every `feTurbulence` image changes.
  - `feDiffuseLighting` and `feSpecularLighting`: `lighting-color` is converted to linearRGB when the primitive works in it (it was used as a linearRGB value), `lighting-color="inherit"` is the parent's (it was white), a light's position is in `primitiveUnits`, a `specularExponent` outside 1–128 is used (the primitive was transparent), a spot light's negative `specularExponent` is used (it was 1), `kernelUnitLength` spaces the normal's samples (it was ignored), and an image two pixels wide or high is lit (it was transparent).
  - `feImage` draws an element at its own coordinates in the filtered element's user space, with the element's whole transform and, under `objectBoundingBox`, in the box's space (it was drawn from the sub-region's corner at the device scale); an image is placed with the whole transform (rotation and skew were dropped); a filter of an element inside an feImage has its own region (it was cut to the feImage's); an feImage on a circle of references is transparent, and an element whose filter draws itself is no longer drawn unfiltered.
  - `feColorMatrix`: `hueRotate` in f64 (90° and 270° differed by one in a channel), `saturate` above 1 or below 0 used (it was clamped), `luminanceToAlpha` with 0.2126, 0.7152, 0.0722 (it was SVG 1.1's 0.2125, 0.7154, 0.0721), and `values` of the wrong count, or none, the input unchanged.
  - `feConvolveMatrix`: a kernel of the wrong length, an order that is not positive or a target outside the kernel gives the input unchanged (it was transparent), a divisor of 0 is the kernel's sum (it was transparent), and `kernelUnitLength` spaces the kernel's cells (it was ignored). An order whose product wraps 32 bits no longer fails with `ErrLimit`: its kernel cannot have that many entries, so the primitive is the input unchanged.
  - `feMorphology`: a radius that is zero, negative, left out or not one or two numbers gives the input unchanged (it was 1, or transparent), and one from 2^31 is the whole image (its size wrapped to zero).
  - `feGaussianBlur` with a negative `stdDeviation` gives the input unchanged (the other axis was blurred); `feDropShadow` reads an invalid `stdDeviation` as 2 (it was 0); the last `feFuncR` (`G`, `B`, `A`) of an `feComponentTransfer` counts even with a type that is no type; `feComposite operator="lighter"` is drawn (it was `over`).
  - Sub-regions: under `primitiveUnits="objectBoundingBox"` a primitive's `x`, `y`, `width` and `height` are fractions of the bounding box; one left out is the union of its inputs' sub-regions (it was the filter region), `feOffset`'s result is clipped to its sub-region like any other, and a primitive with no width or height is transparent while the primitives after it still run (the filter ended there).
  - The `filter` property: a reference to no `<filter>` applies no filter, the whole list included (the element was not drawn); a `<filter>` with no primitive in a list hides the element (the others were applied); `objectBoundingBox` units on an element with no width or height leave that filter out (the element was not drawn).
- **breaking:** the rasterizer's work bound (pixels filled and stroked, edges, flattened points, layers, masks, pattern tiles and filter passes) is 128 Mi pixel operations at scale 1, times the scale squared above it, and at least 16 per output pixel. It was 512 Mi at every scale (or 16 per output pixel): a PNG whose work is between 128 Mi and 512 Mi operations at scale 1 now fails with `ErrLimit`. The bound is lower than before below scale 2 (a quarter at scale 1), the same at scale 2, and higher above it, as the pixels are (2.25 times at scale 3). The heaviest chart of the 3,470 in the corpora (in-repo, wild and Deneb) spends 23 Mi operations at scale 1, 5.5 times under the bound (5.6 at scale 2, 5.7 at scale 3); every chart renders as before, and a test holds each to half the bound. The corpora have no filters, and filters are where SVG input reaches the bound first: a Gaussian blur over the whole canvas costs about 49 operations per output pixel, a drop shadow 56, so a 1024×1024 canvas under a chain of ten primitives (200 M operations, 192 per pixel) now fails at scale 1, where 512 Mi allowed it. The new option `WithPixelWorkLimit(ops)` sets the budget at scale 1 (the scale rule and the floor still apply), so such input can have its headroom back (`WithPixelWorkLimit(512 << 20)` is the old bound at scale 1), or untrusted SVG a tighter bound; zero is refused, and the limit error names the option. A document built to spend the whole bound stops in a quarter of the time. The `label` transform's bitmaps and a PDF's images of colour glyphs have the bound at scale 1 for their pixels (it was 512 Mi). See [docs/limits.md](docs/limits.md).
- **breaking:** PNG (SVG input): a filter region over its bound (32 Mi pixels), and style sheets over theirs (size, rules, matching work), fail the call with `ErrLimit` instead of leaving the element undrawn or the document partly styled without a word.
- **breaking:** a transform field given as an expression (`{"expr": …}`) has no name, as upstream's, so the outputs named after it are upstream's: `fold`'s key is `undefined`, `flatten`, `project`, `lookup`, `impute`, `regression`, `loess` and the group-by fields of `aggregate`, `joinaggregate`, `kde`, `kde2d` and `quantile` write a field named `"undefined"`, a measure is named after its op alone (`sum`), and `bin` names its signal `bin_undefined`. They were named after the expression's text, or its `as`, which upstream ignores.
- **breaking:** a `monotone` interpolation whose `orient` is neither `horizontal` nor `vertical` fails the render, as upstream's ("curve is not a function"), instead of drawing as `vertical`.
- **PDF text (breaking for output):** the font of PDF text is read from the SVG's `font-family`, `font-size`, `font-weight` and `font-style` themselves. A numeric weight such as `fontWeight: 450` drew text at 450 pt; a font size of 1e6 at 6 pt, -20 at 20 pt and 0 at 11 pt. Text of size zero is now not drawn, and a negative size is ignored as invalid. Text measurement parses a CSS font string by the grammar of the canvas context upstream measures with (node-canvas): `450 12px Arial` is weight 450 at 12 px, not 1,025 px wide; a line-height after the size is not the size; `bold italic` is both in either order; `lighter` is 100.
- **PDF (breaking: fewer errors):** `SVGToPDF` and the PDF methods ignore a presentation value that does not parse, as SVG does, instead of failing the whole PDF: a data-driven colour that is not one, `currentColor` (now the `color` property, black by default), an opacity of `"half"`, a `strokeCap` of `"Round"`, a transform made from a word position. A `NaN` or infinite stroke width, dash or miter limit was written into the content stream as an invalid PDF with no error; numbers in the content stream are now always finite, and a drawing that overflows to infinity fails with an error. Path data with an error (upstream writes `NaN` for a null value) is drawn up to it. `blend` (`mix-blend-mode`) is drawn under PDF's blend mode, gradients with translucent stops (an area fading to transparent) under a soft mask of their alpha, Vega's `<pattern>` around a radial gradient as the gradient, a scaled path mark's `vector-effect="non-scaling-stroke"` with its stroke in page space, and `fontVariant` as normal text, as in the PNG; each failed the PDF. Text on a `<text>`'s own `x` and `y` is drawn. A mark with an `href`, which Vega wraps in `<a>`, failed the PDF; it is drawn, with a Link annotation opening its URL (`http:`, `https:` and `mailto:` only; any other URL in the SVG is no link). Error messages quote at most 64 bytes of the document.
- **breaking** for scripts that test for 1: CLI: every invalid flag value exits 2, as documented (C73) — `-text x`, `-from x`, `-timeout -1s`, `-scale 0`, an unknown `-version` or `-timezone`, a missing `-theme`/`-font`/`-allow-file` — and so do no command and an unknown command.
- **breaking:** CLI: a Vega-Lite spec without `$schema` is rendered as Vega-Lite. It used to be rendered as Vega, which drew an empty 0×0 chart with exit status 0. Input is now detected by `$schema`, else by its top-level properties, and an ambiguous input is an error. New `-from vega|vega-lite|auto` ([ADR 0008](docs/adr/0008-cli-language-detection.md)).
- **breaking:** CLI: failed loads and evaluation errors fail the command (exit status 1), with a hint when the cause is that no `-allow-http`/`-allow-domain` was given. New `-lenient` renders past them, printing each. Warnings are printed to stderr.
- **breaking:** the views a Vega-Lite specification describes are counted before any is built, against one budget, `WithMemoryLimit`/32 KiB (65,536 by default; [docs/limits.md](docs/limits.md)): nested and layered repeats multiplied past the old per-repeat bound of 10,000 (four nested repeats of 30 fields, 1 KB, reached 985 MB). Past it the compile fails with `ErrLimit`.
- **breaking:** a Vega-Lite value of the wrong type fails where upstream's compiler throws, in 6.4 and in 5.8 mode, with upstream's message ([ADR 0013](docs/adr/0013-invalid-input-fails-where-upstream-throws.md)): `"layer": {}`, `"transform": {}`, `"params": 1`, a field `type` that is not a string, a time unit without a unit, the legacy `in` predicate (which upstream accepts but never reads), and, under 5.8, primitive channel definitions, transforms and data. These compiled to a blank or partial chart with no error. Where upstream compiles such a value, aster compiles it to upstream's exact output with upstream's warnings: JavaScript's arithmetic, string conversion and key spreading of values of the wrong type, and the prototype semantics of the plain objects upstream keys by field name, so a column named `constructor` or `__proto__` compiles as it does upstream, within one compilation and without carrying over to the next (a differential of 886,129 type-confused corpus specs against node, comparing errors, warnings and compiled Vega, finds no difference; it now also runs nightly with a new seed, and each divergence it finds is kept as a regression mutant). A repeat's `row` or `column` given as a string repeats over its characters, as upstream does.
- **breaking (fewer successes):** with `WithMemoryLimit(n)`, the `label` transform's drawing of the marks it avoids holds its pixels within the PNG canvas bound (`n`, between 4 MiB and 1 GiB, [docs/limits.md](docs/limits.md)); it had the rasterizer's 1 GiB whatever `n`. A label avoiding a mark drawn through a layer as large as the layout (filled and stroked at an opacity) holds 64 MB at 1000×1000, and fails with `ErrLimit` under a 32 MiB limit.

### Bounds and limits

- Each call has a ledger that every stage charges, before allocating, for the memory the input makes it allocate, and that the loops the input controls charge for their work, polling the call's timeout. `WithMemoryLimit(n)` bounds it at `n`; without it, at 2 GiB ([docs/limits.md](docs/limits.md)). A render past it fails with `ErrLimit`. ([ADR 0010](docs/adr/0010-bounds-charged-where-work-happens.md))
- New: [ADR 0011](docs/adr/0011-faithful-output-free-algorithm.md), "faithful in output, free in algorithm".
- PNG (SVG input): an offscreen layer (an opacity group, a shape filled and stroked at an opacity, a blend mode, a mask) holds the pixels drawn into it, not the whole canvas, and one given back is reused, so nested opacity groups hold at most three canvases at once however deep. A document refused for its layers' memory may now render, bounded as any other by the pixel work budget and the timeout: sixteen nested opacity groups over an 8000×8000 canvas were refused at once, and now draw until one of those stops them. Output is unchanged.
- Caches shared between calls are bounded by the bytes they hold, not by their number of entries: compiled expressions and regular expressions, custom symbol paths, and per converter the measured widths, CSS fonts, font fallback lists and glyph outlines. A 419-byte specification could keep 900 MB of compiled regular expressions alive after its render; a hostile CJK label under many font families, hundreds of MB.
- The timeout reaches into image work in PNG and PDF output. Converting a decoded image's pixels, halving it for a small drawing, splitting and compressing it for a PDF, filling the background and finishing the canvas each check it every 65,536 pixels, and decoding checks it as the image's bytes are read: a PNG every quarter of a million pixels or so, however well it compresses. None of these checked it: an SVG of 16 `<image>` elements sharing one 533-byte, 2048×2048 PNG ran to the end of its first image's work, 4.4 s past a 2 s timeout on a CI runner. The rasterizer charges converting and halving to its pixel-work bound, and a colour glyph painted as an image for a PDF honours the timeout too. Output is unchanged.
- The timeout reaches into filters in PNG output. Each filter primitive (blurs, drop shadows, offsets, floods, blends, composites, merges, colour matrices, transfer functions), its conversions between colour spaces and the copy of its result check it every 65,536 pixels of each pass they make, as do compositing an opacity group, a COLR glyph's group or a filter's result, applying a mask and intersecting two clips. Only the boundaries between primitives checked it: a render of 3000×3000 filter regions ran up to 0.99 s past its deadline on two cores (0.76 s past 200 ms on CI's macOS runner), and now up to 0.09 s. A filter's passes are charged to the rasterizer's pixel-work bound as they run, a blur's for each of its passes and channels, where a primitive was charged one pass before it ran: a blur is charged 40 to 80 times what it was, so filter-heavy SVGs reach `Limits.MaxPixelOps` sooner (a filter whose primitives cannot fit what is left of it still fails before it starts). Intersecting two clips is charged too. Output is unchanged.
- PNG (SVG input): the filter primitives drawn since this release are bounded by what they cost: each pass charges `Limits.MaxPixelOps` a band at a time, polling the timeout, by its real work (an `feConvolveMatrix` its kernel's taps for each channel of each pixel; an `feMorphology` a constant a pixel, whatever its radius). An `feConvolveMatrix` kernel of more than 65,536 taps fails with `ErrLimit` ([docs/limits.md](docs/limits.md)); resvg runs it, for days at the sizes the input can choose, or crashes when `orderX` × `orderY` wraps a 32-bit count. An `feTurbulence` computes at most 2,099 octaves, the image any larger `numOctaves` gives, and is charged its octaves times its channels a pixel. An `feImage` fetches a URL href through the Loader as an `<image>` does, under the same limits and charged to the call's ledger; one drawing an element is a layer, so a chain of them is bounded by the layer depth, and a cycle ends where it meets the filter being applied (an element whose filter is the feImage's own is drawn unfiltered, as resvg does).
- The timeout reaches into the start of a Vega render and into JSON parsing. Parsing a Vega specification into its dataflow (signals and their updates, data sets, scales, marks and their encodings, axes and legends, the merged config) and building that dataflow (its operators, their parameters, and the inline or parsed rows it is seeded with) checked the timeout nowhere: 4,000 Vega-Lite selections ran up to 0.39 s past a deadline under `-race`. Each of their loops now counts its steps, which checks the timeout about every millisecond of work. Parsing JSON (the specification's, a `values` string, a loaded data file) checks it as it reads, inside a long string or run of white space too; a call whose time is up stops there, with the context's error naming the parse. Two quadratic constructions are linear: the expression of a signal update with many event sources, and of an encoding's rules after an unconditional one with a long field path (4,000 segments allocated about 78 MB). Output is unchanged.
- The rasterizer's cache of pattern tiles and of decoded colour glyph bitmaps is charged to the call's ledger, so `WithMemoryLimit` bounds it (it was a fixed 256 MiB).
- Parsed path data (custom symbol shapes and `path` marks) is charged to the call's ledger; a path string parses to sixteen times its size.
- `SVGToPDF` and the PDF methods report a limit reached inside a stage that cannot return an error as `ErrLimit`, as the other outputs do, rather than as an internal error.
- The timeout reaches into the rest of a Vega render's dataflow and Vega-Lite's compile. The dataflow's own operators (collect, the data join, the item store, mark, encode, the sorts of a collect, a `values` domain and a mark's items, a relay's copies, a lookup index, a band or ordinal scale's domain) charge their per-row loops a batch of rows at a time, and a sort a step per comparison: over 100,000 rows a render ran 55 to 99 ms without checking the timeout, now 3 to 7 ms at most (a collection of the garbage). Vega-Lite's compilation charged nothing, or a step for work linear in the specification, in reading a config, a `format.parse`, a `selection` or a flatten's `as` given as a string (each key read the whole string again: quadratic, a second for 20,000 characters), in deleting many config or parse keys one at a time (quadratic: 5.6 s for 20,000), in a long field path's guard expression (25 million allocations for 5,000 segments), in an event selector, and in the axis configs every axis reads again; each is now linear and metered, and the 20,000-key and 20,000-character cases compile in 30 to 70 ms. Parsing JSON polls inside a long number literal too, and a literal of more than 800 bytes is converted from its 800 significant digits, a sticky digit and its exponent, which is exact: Go's `strconv.ParseFloat`, which the parse used, misreads a literal with more than 800 digits before its decimal point near a halfway case (a 1,783-digit integer times `1e-2100` read as 0, where `JSON.parse` reads `1e-323`), and now such a literal reads as `JSON.parse` reads it. A JSON document held as a string (a data set's `values`) is parsed in place, not copied first. Output is unchanged on the corpus.
- `format.parse: "auto"` finds a CSV header's repeated columns in linear time (65,536 columns took 6 s, unpolled) and parses the fields in upstream's `Object.keys` order, array-index names first and no `__proto__`; a `format.parse` object's illegal pattern is reported for the field upstream names first.
- Vega-Lite compilation honours the timeout in every phase, from copying the input through normalization, parsing, the dataflow optimizer and assembly: each loop over views, selections, params, transforms, encodings, dataflow nodes and the values they hold charges the call's ledger. A spec with 100,000 point selections, which compiled for eight and a half minutes and returned up to six seconds past a 1 s timeout, now compiles in about 2.5 s and stops within milliseconds of the deadline.
- Vega-Lite compilation is no longer quadratic in a spec's views and selections where upstream's algorithm is (output unchanged, ADR 0011): the dataflow optimizer's child removals and insertions, its deepest-first node order, the ordering of root data sets, and the brush test every point selection repeats.
- Geographic work is bounded where it happens. The path-point budget counts the points a projection produces, after resampling and before its clip extent, so a tiny `precision` with a clip extent that drops everything fails with `ErrLimit` instead of running for seconds and allocating gigabytes; the measuring walk of a projection's `fit`, and `geoArea`, `geoBounds` and `geoCentroid` in expressions (with or without a projection), are bounded and stop at the timeout like a mark's paths. Decoding TopoJSON charges what it makes to the ledger first: one long arc referenced thousands of times no longer allocates gigabytes. Graticules charge their points. The clip circle's walk is bounded by construction, and polygon clipping rejoins its pieces in linear time (it was quadratic in the pieces). Charts render as before.
- Expression functions are metered and charged by construction: every call and every pass or loop over a string or array charge their work to a plain counter that reports to the call's ledger every 1,024 units, and every string or array a function builds goes through builders that check the length limit and charge the expression string budget before they allocate (C23). `indexof`, `lastindexof`, `split` and `replace` search in linear time whatever the input (C21: a needle of 4M characters ran for hours); `extent` of a string or an array-like object no longer re-encodes or walks every index up to its `length` (C22); `split`, `timeSequence`, `merge`, `pluck`, `slice`, `reverse`, `sort`, the selection functions and `lassoPath` are charged for what they build. A test calls every function of the table with hostile arguments and checks its time and allocations against what it charged.
- Regular expressions are charged to the call's ledger as they are compiled: literals when the expression is parsed, patterns from strings when they are made, given back once the shared cache keeps them (C8: a 419-byte spec reached 923 MB). A pattern goecma262 rejects is remembered, so one past its size cap is not parsed again for every datum; a pattern source over 1 MiB fails with `ErrLimit`. A regular expression literal with the `g` or `y` flag shares its compiled program between evaluations instead of compiling again each time.
- A regular expression is paid for before it allocates, with goecma262's bounds (since v0.3.0): its parse first, by the source's length (1 KiB and 128 bytes a byte), then its compiled form, which goecma262 bounds from the parsed pattern and holds to what was paid (`WithBudget`); it is refused unbuilt with `ErrLimit` when the ledger has no room, or when it would pass goecma262's program cap, and the charge is trued to what the pattern holds (`MemoryFootprint`) once it is built. Before, the second of two such patterns was compiled in full (seconds under the race detector, past `WithTimeout`) and only then refused (#115), and goecma262's parser, which allocated about 190 bytes a byte of source (200 MB for a MiB), was not charged at all. The bound before the compile is now within a few kilobytes of what a pattern holds (the parse bound and a few hundred bytes more): `(a{1000}){190}`, which holds 30.7 MB, is paid 30.7 MB, where aster's own estimate asked 61 MB for it (from 1.2 to 18 times what a pattern held), so a pattern near the limit is no longer refused when it fits. The estimator that followed goecma262 v0.2.0's compiler (and read its unexported program by reflection) is gone. `countpattern` pays for its two patterns the same way. The deadline stops the parse, the bound's walk of the parsed pattern and the compile.
- The deadline stops a regular expression's parse, its compile and its searches, which goecma262 polls as it works: a search of a long string ran to its step budget (about a second for 6 MB) past `WithTimeout`, and a compile could not be stopped. Each search holds for backtracking at most what the call's ledger has left, and goecma262's default bound otherwise (256 MiB and 32 bytes a byte of input). `test` and `regexp` are held to the class guard of every expression function (time after the deadline, allocations against what was charged), from which they were exempt. A search from `lastIndex` (`test` of a `g` or `y` pattern) and a scan of matches that begin or end between the halves of a pair (`replace`, `split`) run the pattern's own program: they compiled a second copy of it, charged to the ledger, for each call.
- Concatenating a string with an array (`'' + arr`) and a chain of `+` charge the string budget once for the result, not again for every prefix (C44): 5,000 strings of 20 bytes no longer exceed it.
- A `voronoi` over coordinates whose squares overflow (such as `-1e308`) or that are infinite or NaN looped forever and killed the host process with a fatal out-of-memory. It now gives upstream's cells for every such input (d3-delaunay reads an unset seed and unset hull links as `undefined`, which the port now models, along with V8's typed-array sort and robust-predicates' early exit), and every walk over the triangulation is bounded by its size; links that would make upstream loop forever fail with `ErrLimit`. An exception a `voronoi`'s `x` or `y` accessor throws reaches the dataflow as the specification's error instead of a "degenerate input" error.
- The memory of `kde2d` and density `contour` rasters, contour rings, `voronoi` triangulations, `aggregate` and `pivot` cell state, `label` masks and bitmaps, and the `wordcloud` board is charged to the call's ledger before it is allocated, so `WithMemoryLimit` bounds it: a `kde2d` of three groups at 4,000² held 1.5 GB, a 2,500-column `pivot` 1.5 GB under a 256 MiB limit. `density` reserves its samples as rows before drawing them, and `countpattern` its distinct tokens. `label` masks take a bit a pixel instead of a byte.
- Contour hole assignment, quadratic in a grid of isolated cells (8 s for 1024², and success after the deadline), indexes each long ring and tests a hole only against the edges near it, with upstream's predicates: the same output, in time linear in the holes. What it still does is metered, so `WithTimeout` ends it.
- A `window` gives every row of a frame that only grew upstream's one shared `values` array, instead of a copy per row (250 MB for 4,000 rows with `frame: [null, null]`; now one array). Frame offsets are numbers as upstream adds them: `Infinity` or `1e300` reach the end of the partition (they wrapped to the smallest int, giving `undefined` sums), and NaN, fractional and crossing frames give upstream's results and errors. `lag` and `lead` past the partition give `null` (an offset of 1e9 or more was read as 1).
- The strings `format()`, `timeFormat()` and `utcFormat()` write in expressions are charged to the expression string budget, and a time format stops at it: a specifier of a few KB could write megabytes per call.
- PNG: the rasterizer's path geometry is bounded and charged as it is built. Glyphs and paths wholly outside the canvas or clip are not flattened, and of a curve sweeping far beyond the canvas only the points of its visible part are kept (the image is the same); the points held at once (new budget, `n/16` points) and the points and edge crossings computed (the pixel-operation budget) are charged. A 4 KB Vega-Lite text mark at font size 100,000 took 736 MB; it takes 12 MB.
- PNG: an image is decoded once however many elements draw it, and what it decodes to is charged to the ledger before it is decoded; the pixels of one image are bounded by `WithMemoryLimit` (`n/16`). Eight elements drawing one 8192×8192 image took over 1 GiB under a 64 MiB limit; the image now fails with `ErrLimit` before it is decoded, and one within the bounds is decoded once. A broken image is reported once.
- PNG (SVG input): every buffer of a filter chain (results, colour-space copies, blur scratch) and every clip coverage map is charged to the canvas budget (`WithMemoryLimit`), instead of a fixed 1 GiB, and a merge node counts as a pass over the region and polls the timeout: twenty results kept to a final merge took 357 MB under a 64 MiB limit, and 600 merge nodes ran 11 s past a 2 s timeout. `SourceAlpha` is made once per filter.
- `WithQuantizePNG` and `WithRecodePNG` run under the call's timeout and memory limit, on the image the rasterizer drew rather than its PNG decoded again; a call past either fails with its error. An image of more than 65,536 distinct colours is not quantized but recoded losslessly at once: quantizing a 2000×2000 gradient image took 3.9 s, past a 2 s timeout, and succeeded. The documentation no longer says quantization is "always safe" at "tens of milliseconds". Encoding the PNG (the rasterizer's, the quantized or the recoded one) polls the timeout per row instead of running a whole image without a poll: on CI a 2000×2000 image ran 1.3 s past the deadline. The bytes are image/png's as before.
- The per-render caches of gradients, glyph outlines and SVG glyph documents are bounded by their bytes and charged to the ledger.
- PNG: marker-mid on a path of many closed subpaths took time quadratic in its segments.
- The list of tuples each dataflow operator hands on (a filter's, a sort's) is charged to the call's ledger, replaced when the operator runs again: 400 filters over the same 120,000 rows made a gigabyte of lists under `WithMemoryLimit(64 MiB)`.
- Data triggers and view resizes are bounded where upstream loops (C11): 16 changes by the triggers of one data set, and 16 resizes, in each run (the first, and each signal write's), and nested 256 deep at most. They shared one counter for the whole render, so 17 independent data triggers, or 17 signal writes that each resize the view, failed with `ErrLimit` under the default settings.
- Delimited data (CSV, TSV, DSV) charges each row before making it, its weight with `WithMemoryLimit`, so a header of many columns over blank lines stops at the bound instead of allocating gigabytes; a header of more than 65,536 columns fails with `ErrLimit`, and the error names the bound reached (C19). A delimiter of more than one byte (`é`) splits on its first character, not on its first byte, and a `header` is joined with the whole delimiter, as upstream's (C91).
- Warnings are bounded (C20): each distinct warning is reported once per call, its text cut to 1 KiB, and at most 256 are reported. A scale with a long unknown property in a faceted group warned in every cell and kept every copy.
- The weight of a row of more than 32 fields counts the hash index of its keys, which a row of a thousand fields holds 88 bytes a field with (it was charged 56).
- The data and the images of one call share one allowance of loaded bytes, as limits.md says (C80); each had its own, so a call could load twice the budget.
- The specification's JSON parse is bounded by default (1 GiB, as documented) (C40): without `WithMemoryLimit` the bound was 0, which meant none. The limits doc test now reads the values the call sites use.
- Vega-Lite compilation is linear where it was cubic or quadratic, with output unchanged (ADR 0011): JavaScript's key order (array indices first) is kept lazily or once per object instead of on every insert (an 8 KB spec of descending numeric keys ran for seconds, 70 KB for hours; a long string spread as a mark part, the ancestor parse and other key maps likewise); selection signal names resume their counter per name; a shared axis title, selection data and top-level selection signals no longer redo the work of every earlier view.

### Fidelity

Where the output differed from upstream Vega and Vega-Lite, it is now upstream's.

- PDF text follows SVG's whitespace rule, as the PNG does: tabs and newlines are no longer drawn as `.notdef` boxes, and runs of spaces collapse.
- PDF text extraction: a glyph used in right-to-left or combining text no longer extracts, everywhere else in the document, as the text of the cluster it first appeared in (`"ab שלום cd"` made every later space extract as `" שלו"`); a glyph that stands for different text in different places carries its text as ActualText.
- `PDFTextNamed` declares a CFF font as a `CIDFontType0` (it was a `CIDFontType2`, a TrueType font's), and the PDF methods other than the `*Usage` ones no longer copy each font program for a usage report nobody asked for. A glyph whose outline cannot be read is not drawn, as in the PNG, instead of failing the PDF with an error blaming bitmap fonts.
- A float-to-integer conversion of a far-out gradient parameter, mesh coordinate or arc sweep in the PDF writer could differ between amd64 and arm64.
- `defined`, `aspect`, `smooth` and `aria` (of an item, and `aria` of a mark) treat only `false` as false, as upstream does: a `defined` of `0`, `""` or `NaN` no longer breaks a line or area, an `aspect` or `smooth` of `0` no longer changes an image, and an `aria` of `0` or `""` no longer hides a mark. Each reads back in expressions as the value given.
- A text whose `x` or `y` and `angle` are all strings had the angle escaped twice.
- An axis whose `orient` is a signal failed to parse its encoding when a config value was an array holding `null` (`tickDash: [4, null, 2]`) or a string holding U+2028 or U+2029; both are now spliced as upstream's `stringValue` does.
- Expressions match V8 where they did not: `exp`, `log` and `tan` are V8's (C45: 16%, 0.08% and 34% of results differed in the last bit), as are the `log` scale's `Math.exp`/`Math.log` with base e; an object literal with a quoted key that vega-expression rejects (`{"toString": 1}`, `{"__proto__": 1}`) or the key `then` is a compile error, as upstream (C96); `in` finds the members an object, array, date or regular expression inherits (`"toString" in {}`, `"push" in []`); concatenation joins a high surrogate to a low one, so `"\uD83D" + "\uDE00"` is `"😀"`, and `indexof`, `lastindexof`, `split` and `replace` find half of a pair; `split` ignores a separator's `y` flag; the string length limit counts UTF-16 code units, not bytes (C97); comparing two characters above U+FFFF that share a high surrogate, or a lone surrogate, orders them by code unit in transforms and scales too (C98).
- `getIndex` of a number past 2^31 (`arr[1e19]`) read an element on some platforms; it reads the property, as JavaScript does.
- JavaScript's 32-bit integer conversion (`~~x`, `x | 0`) of a huge number, in text width estimates and a crossfilter's `ignore` mask, wrapped as on no JavaScript engine and differed between amd64 and arm64.
- TopoJSON decodes as topojson-client does. Without a transform, positions are the input's arrays, with their own length and their values as they are (a `null` or string coordinate stays one, where it was turned into a number and every position padded or cut to its arc's first position's length). With one, the running sums and the translation are JavaScript `+`, so a string coordinate concatenates as upstream, and a position of fewer than two numbers is padded to two. Mesh stitching matches arc ends by their JavaScript string, and an arc counts as empty by the truthiness of its second position's values.
- A `topojson` data format with a `mesh` and no `feature` failed with "Invalid TopoJSON object: undefined"; it now decodes the mesh.
- A graticule's point count is `d3.range`'s, a 32-bit conversion: a step so small that the count passes 2^31 is the `RangeError` upstream throws, or wraps as upstream does, instead of an `ErrLimit`.
- PNG: a gradient whose geometry overflows (`x2="1e-160"` with `spreadMethod="repeat"`, a radius of `1e-320`) failed the render with an internal error. A linear gradient shorter than tiny-skia draws is now one colour as in resvg (the last stop's when padding, the average of its colours when repeating or reflecting), a radial one too small paints nothing, and no colour table or image index is computed from NaN. Overflowing transforms of images and paths no longer index out of range, and the number of segments of a curve whose coordinates overflow no longer differs between amd64 and arm64.
- PNG and PDF read an image URL whose scheme is upper case (`DATA:image/png;…`) as the inline image the SVG writer drew, instead of sending it to the Loader and failing the call.
- PNG: `vector-effect="non-scaling-stroke"`, which Vega writes on path marks it scales, is honoured (SVG 2): the stroke keeps its width, as in a browser, instead of being scaled with the path. resvg ignores it, so such charts no longer match resvg's PNG, which was wrong.
- PNG (SVG input): an element whose font size is not set, or set invalid (negative), takes CSS's initial `medium`, 16px, as browsers and the PDF writer do, rather than resvg's tool default of 12px. Vega always sets a size; a negative `fontSize` now draws its text at 16px.
- A `stack` groups by `JSON.stringify` of its group-by values, as upstream does: objects and arrays by their content (they all grouped together), dates by their ISO string, and a value that contains itself is upstream's `TypeError`.
- `nest`, `stratify` (and `treePath`/`treeAncestors` lookups), `kde2d` groups and `wordcloud` text write a date key as `String(date)` does, to the second in the view's zone, as the other transforms do; they wrote epoch milliseconds.
- An axis's ticks and labels and a legend's entries come from one implementation of vega-scale's helpers, where two copies had diverged. As upstream: a boolean `tickCount` is its number, an unknown interval name or a `step` that `every()` rejects gives the default count (they failed), an interval `step` on `quarter` fails, a `null` count reads as 0 where an undefined one hides log labels, and a range label of no finite value reads "≥ null".
- `timeOffset`/`utcOffset` of many quarters (and every offset of an `every()` interval) searches each boundary afresh, as d3 does: 33,000 quarters gave an Invalid Date. `millisecond.every(k)` and `year.every(k)` keep a step above 2^40 (it was clamped, moving the ticks). A descending piecewise domain is reversed whole before it is paired with the range. Parsing a number in a date skips JavaScript's Unicode white space, as `\s` does. A fractional `schemeCount` on an ordinal scale fails as upstream's `new Array` does. `week.every(k)` in a zone with daylight saving finds its boundaries for any `k` (past 65,536 weeks it gave an Invalid Date), and `%Z` in a time parse counts its window in UTF-16 units, as d3 does.
- A trigger that fires again for a data set before its first change set is applied no longer drops the first: both are applied, as upstream does.
- The `Infinite extent` warning is upstream's, bounds included (`Infinite extent for field "x": [Infinity, -Infinity]`), and a Load reads `values` only when they are truthy, as upstream does (C93).
- A colour value reference (`{"color": {"r": …}}`) in a group with signals failed with `ReferenceError: datum is not defined` and drew no fill (C46).
- A boolean item property set to `null` (`defined`, `aria`, …) reads back in expressions as `null`, not `undefined`.
- `format.parse` no longer writes into the specification's inline values (C94).
- `data('x')` of a data set whose values have not been computed yet is `null`, as upstream's, so `length()` of it is upstream's `TypeError`; the selection functions raise it too for such a store. It read as an empty array.
- The copies a derived data set hands on are tuples of their own, with new ids, as upstream's `derive` makes them: a sort's ties among them follow the order they were copied in.
- `inScope(x)` finds the item it is given by identity and raises upstream's `TypeError` for a value that is not an item; it read a number off the value, converted to an int differently on amd64 and arm64. A `resolvefilter` reads a tuple's `_index` as a property key, as upstream does (`1.5` and `"01"` select no row).
- A `crossfilter` hands on the indices of its tuples, as upstream's does, with the tuples as the data set's source: a mark or a transform that reads what the pulse adds right after it sees numbers (a `formula`, `bin`, `timeunit`, `identifier` or `window` there is upstream's `TypeError`), and a `resolvefilter` maps the indices back to tuples. `data()` of a data set that a `resolvefilter` filters is its unfiltered source, as upstream's; an `extent`, `stack`, `pie`, `impute` or `joinaggregate` reads the source as upstream's does. A derived data set's copy of a number is an empty tuple.
- A `force` gives a node without velocities `vy` before `vx`, as d3's `node.vx = node.vy = 0` does.
- Each image URL goes through the Loader once per call (C35). PNG and PDF output drew from what the SVG stage resolved only by sanitizing the href it wrote a second time: a rewriting Loader saw its own answer, a Loader of logical names refused it and the image vanished from PNG and PDF, and a failure was reported twice, once as "not a data: URI". One table per call now carries URL, sanitized URL and bytes or error between the stages; each failure is reported once, as the URL the spec names (`LoadError.URL`). A link's URL is sanitized once per call too.
- Fixed: embedded `data:` images drew nothing with the default loader, because they were sent through it and refused. Embedded PNG, JPEG and GIF images (`data:image/png`, `…/jpeg`, `…/gif`) are part of the specification and now draw with any loader; other `data:` URLs are still the Loader's to allow.
- A faceted group over a `field` (PreFacet) raises upstream's errors: "PreFacet does not support field modification." when the field parameter is a signal, or when a tuple it faceted comes back with that field rewritten (a formula that ran again after a signal write); and the `TypeError` of `field(t).forEach` for a value that is not an array. It ignored the first two and faceted nothing for the third.
- Long chains of operators compile: an explicit `sort` of 200 or more values, an `or` of 1,000 predicates or a long sum failed with "expression too deeply nested" in the Vega-Lite compiler, which upstream compiles. Expression nesting has one bound, 512, in the compiler and in Vega.
- PNG (SVG input to `SVGToPNG`): a `<use>`'s `clip-path`, `mask` and `filter` are in its coordinates after its `x` and `y`, as resvg's are (usvg makes the use a group whose transform ends with `translate(x, y)`). They were in the coordinates before them: a user-space clip or mask was off by `(x, y)`, and a filter's layer was laid out in one system and the filter run in the other, so an offset or a sub-region landed off by `(x, y)` and was cut. A `<use>` of a symbol or of an `<svg>` is unchanged.
- PNG (SVG input to `SVGToPNG`): `feColorMatrix type="hueRotate"` computes its angle and the angle's cosine and sine in f32, as resvg does (they were f64): at 90° resvg's cosine is −4.37e−8, the matrix's zeros fall a few ulps below zero and a channel truncates one lower. A rotation by 90° was 1 off in linearRGB (up to 4 in sRGB) on about a tenth of the pixels against resvg (RMSE 0.69, max 15); it is now exact on a source both draw alike, and at RMSE 0.28 on anti-aliased shapes, as the other colour matrices are.
- PNG (SVG input to `SVGToPNG`): filters draw `feTile`, `feMorphology`, `feConvolveMatrix`, `feDisplacementMap`, `feTurbulence`, `feDiffuseLighting`, `feSpecularLighting` and `feImage` as resvg does (each was a transparent result, so an element whose filter ended in one vanished). On a source both renderers draw alike they agree exactly, invalid parameters included (usvg's transparent "dummy" for a convolution's bad order, target, divisor or kernel length; a morphology radius that is zero, negative or not one or two numbers). A morphology costs the same whatever its radius, where resvg's costs the radius squared a pixel. A filter region larger than its layer (four times the canvas) is cut to the layer before its primitives' sub-regions are measured from it, as resvg does: a primitive with its own sub-region in such a filter was cleared everywhere.
- Smaller fidelity fixes: a lone-quote date parse pattern, a `null` datetime part, an `autosize` that is a number or array, `config.signals` that is not an array, `titleCase` of a non-ASCII first letter, and datetime selection values with huge or non-finite parts (read through Go integers, platform-dependent) now compile as upstream's do. A legend binding whose event stream holds an array no longer fails with an internal error.

### Errors and diagnostics

- New per-call option `WithErrorHandler(func(error) error)`: told of each such error and of each `aster.Warning`, it decides whether the call goes on. To keep the previous output, pass `aster.WithErrorHandler(func(error) error { return nil })`. See [docs/errors.md](docs/errors.md). ([ADR 0006](docs/adr/0006-errors-reach-the-caller.md))
- New `aster.ErrClosed`, returned by every call after `Close` (the error was not matchable before).
- A JSON body with a `null` row is a failed data load (a `*LoadError`) that `WithErrorHandler` can let go, with the data set empty; it failed the render outright (C91).
- An expression's `warn(…)` is reported as an `aster.Warning` ("EXPRESSION" and its arguments); it was dropped (C39). `info()` and `debug()` stay silent, as upstream's logger is at its warning level.
- Negative limits in the internal Vega options mean "no bound" for every field (C92), and internal errors no longer carry a goroutine stack in their message (C105).
- A timeout's message says its cause once (X9): "timed out after 1s: context deadline exceeded: context deadline exceeded" when the stage's error already carried the deadline's text.
- The Vega-Lite compiler's warnings reach `WithErrorHandler` as `aster.Warning`s, with upstream's text, as often as upstream logs them (a typo'd transform, a channel the mark cannot use, an invalid aggregate, …); they were dropped. `VegaLiteToVega` accepts `RenderOption`s (**breaking** only for code that stores the method as a `func([]byte) ([]byte, error)`), of which `WithErrorHandler` applies, and `aster compile` prints them. Like Vega's, each reaches the handler with its text cut to 1 KiB: one place cuts every warning, whatever its source ([docs/limits.md](docs/limits.md)), so a 100 KB field name in an invalid transform is not printed whole.
- A regular expression's limits are told from an invalid pattern by goecma262's typed errors (`ErrLimit`), not by words of the message, which quotes the source: `regexp('too deeply nested(')` was an `ErrLimit` where it is a `SyntaxError`. In `countpattern`, a pattern past goecma262's limits and a search out of its step or memory budget fail with `ErrLimit`, as in expressions; they were errors of no kind. A pattern's error quotes at most 64 characters of its source and 16 of its flags, and flags that are not JavaScript's are refused before anything their length sizes is made (384 KiB of flags allocated 6.7 MB).
- An error names its package and its cause once: a rasterizer or PDF limit read "raster: a filter needs more than 64 MiB …: raster: limit exceeded"; it reads "…: limit exceeded".

### API

- New `WithProjection(name, Projection)` registers a projection type that specifications can name, as `vega.projection(name, constructor)` does upstream: for example, one of d3-geo-projection's (`airy`, `hammer`, `winkel3`, …), which Vega does not register. A type is described as d3-geo-projection builds one: a raw projection for the current parameters (`coefficient`, `radius`, `parallel` and the others Vega forwards), plus the default scale, clip angle, center and rotation. Every projection property, `fit` and `invert()` apply to it as to a built-in type. Types are per Converter, and may replace a built-in name. ([ADR 0016](docs/adr/0016-custom-projections.md))
- **New:** `WithContext(ctx)`, a per-call option every method takes, cancels one call without closing the Converter (C70): the call stops where it is, frees what it holds and fails with `context.Canceled` (or `DeadlineExceeded` past the context's deadline, named as such rather than as `WithTimeout`); the Loader gets a context derived from it, with its values. `VegaLiteToVega` now takes `...RenderOption` for it. A call whose context ends never returns output.
- `Close` may be called from inside a call, from its error handler or a Loader method (C37): it cancels, marks, returns at once, and the Loader is closed when the last call ends. Before, it deadlocked, and so did a render started from a handler while a `Close` waited. Calls hold no lock while they run.
- New `WithFontFallback(families ...string)`: the families that draw, in order, the characters a spec's fonts lack; with none, no fallback. It is also the way to make a system font a fallback. ([ADR 0009](docs/adr/0009-caller-chooses-fonts.md))
- `FallbackLoader.Sanitize` returns the accepting child's rewrite (C42): a link through an `HTTPLoader` with a `BaseURL` was written unresolved.
- The fonts are loaded once per Converter, into one set the layout measurer, the PNG shaper and the PDF writer share (C71): with text measurement off, PNG and PDF each parsed every font again (about 3.8 MB retained per set of eight registered fonts), and `WithSystemFonts` scanned the system twice. `WithFont`, `WithFontFace` and `WithFontInstance` copy the bytes, so a caller reusing its buffer no longer changes later PNG text. An error building the fonts fails the render instead of the label transform silently drawing no text (C77).

### CLI

- CLI: `-allow-file DIR` (repeatable) loads local data through a `FileLoader`, `-base-url URL` resolves relative URLs over HTTP, and they compose (files first) (C72); a refused relative URL's message says which to pass. New flags `-memory-limit`, `-theme FILE`, `-timezone`, `-font FAMILY=FILE`; `compile` takes `-timeout`, `-memory-limit`, `-theme` and `-timezone` too.
- `compile` refuses a spec it detects as Vega.

### Performance

Output is byte for byte what it was.

- A `wordcloud` lays out in less than half the time (the gallery's word cloud: 369 ms to 157 ms). Scan-converting each word's outline kept its edges sorted from one sub-scanline to the next instead of sorting them again for each.
- The `label` transform paints the marks it avoids in about two thirds of the time (the gallery's labelled scatter plot: 87 ms to 60 ms to SVG). It reads coverage from the rasterizer's own canvas, only where something was drawn, instead of converting the whole canvas to an image first.
- PNG output does not draw shapes and text at opacity 0, which Vega emits for every label the `label` transform could not place, and which upstream's canvas renderer skips too (the labelled scatter plot: 181 ms to 87 ms to PNG).
- The `label` transform no longer holds a canvas of the samples it draws the avoided marks at: the rasterizer reports which pixels they ink, and the layers they are drawn through hold only what is drawn. The labelled scatter plot labels in 31 ms instead of 55 ms to SVG, at a peak of 15 MB instead of 78 MB; 300 symbols filled and stroked at an opacity, in 52 ms instead of 110 ms, at 3 MB instead of 63 MB.
- PNG output of shapes drawn through layers takes 43–46% less memory, and of colour glyphs 12% less, in the same time.

Untagged versions from before 2026-10-01 ran Vega in QuickJS on WebAssembly. Users of untagged versions may notice:

- `HTTPLoader` blocks private networks by default; `BlockPrivateNetworks` is ignored (use `AllowPrivateNetworks` to opt out).
- Text is measured with unrounded advances, as browsers do; `WithHarfBuzzTextMetrics()` restores the previous rounding ([ADR 0003](docs/adr/0003-unrounded-advances.md)).
- Renders are bounded by `WithTimeout` and `WithMemoryLimit` and fail with `ErrLimit` past a bound ([docs/limits.md](docs/limits.md)).
