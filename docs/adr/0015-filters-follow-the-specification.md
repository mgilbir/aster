# 0015: PNG filters follow the Filter Effects spec where resvg departs from it

**Status:** accepted, 2026-10-14.

## Context

`SVGToPNG` draws SVG as [resvg](https://github.com/linebender/resvg) does, and resvg is the reference its output is tested against: the raster tests render each case with both and hold the difference to a bound ([api.md](../api.md#svg-input)). The filter pipeline (`internal/raster/filter*.go`, `feimage.go`, `lighting.go`, `turbulence.go`) was ported from resvg's, and usvg's parsing with it, choice for choice, so that a filtered PNG matched resvg's within rounding.

Where resvg follows W3C Filter Effects Module Level 1 (FE1), that port is right. Where it does not, the port carried resvg's departures with it, and the documentation listed them as "resvg's own choices", kept because resvg's output is what the PNG is tested against: an `feDisplacementMap` that moves a pixel by the scale squared, a map read premultiplied, an `feTile` tagged sRGB whatever its input, turbulence from SVG 1.1's gradient table and a stitch tile made of each pixel's own index, a `lighting-color` used unconverted in linearRGB, a light whose position ignores `primitiveUnits`, an `feImage` drawn from its sub-region's corner without the element's transform, a `hueRotate` in f32, and more. A test that compares with resvg cannot tell which of its choices are the specification's and which are its own, and a document drawn by aster then differs from the same document in a browser, or in any renderer that reads the specification, for reasons no user can find in the specification.

## Decision

- **Filters follow FE1** (and SVG 2 where FE1 defers to it) wherever FE1 defines the behaviour and resvg departs from it. Each departure is named in the code where it happens, with the specification's text, and in [api.md](../api.md#svg-input).
- **Where FE1 is silent or leaves a choice open, resvg's choice is kept**: a turbulence pixel sampled at its corner, the nearest pixel for a displacement, whole-pixel offsets, the morphology window's position, the blur's box approximation, how a value in [0, 1] becomes a byte, a lighting with no light source giving a transparent result. Where browsers differ among themselves on such a point, that is said too.
- **Bounds are not semantics.** The limits on a filter's region, layers, pixel work and kernels stay as they are ([limits.md](../limits.md)); following the specification never removes one. Where it would, the bound wins and the conflict is recorded.
- **Each departure is asserted, not skipped.** `filterDivergences` (`internal/raster/filterdivergence_test.go`) lists every case where aster now differs from resvg, with the specification's text, and asserts that it does differ beyond the parity bound the case would have had: a departure that disappears (resvg changing, or aster regressing to resvg's behaviour) fails. What the specification says the case draws is asserted separately, by a `TestSpec*` test (`filterspec_test.go`) against values derived from the specification: a table worked by hand from its formula, or a reference transcribed from its text (the turbulence reference code, its random number generator's own test value), not a call to the code under test. Every such test was seen to fail with resvg's behaviour planted back.

## Why

The PNG is aster's rendering of the user's SVG, not a copy of resvg's. resvg is a good reference because it follows the specification closely, so its output is the right expectation wherever it does; where it does not, matching it bit for bit is matching a bug. The specification is the one authority a user, a browser and aster share. Keeping resvg as the reference everywhere else keeps the large body of parity tests, which still catch every regression in the primitives' arithmetic.

## Consequences

- **Named divergences from resvg**, each asserted by a test (the list in api.md and `filterDivergences`): `feDisplacementMap` (the scale once, the map non-premultiplied, `in` in its own colour space, per-axis `objectBoundingBox`); `feTile` (the input's sub-region as the period, transparent outside the region, the input's colour space); `feTurbulence` (FE1's gradients, the sub-region as the stitch tile, the seed untruncated, `numOctaves` an integer); lighting (`lighting-color` converted, inherited, light positions in `primitiveUnits`, any `specularExponent`, two-pixel images, `kernelUnitLength`); `feImage` (placement in the filtered element's user space with its whole transform, `objectBoundingBox`, circular references transparent, an inner filter's own region); `feColorMatrix` (`hueRotate` in f64, `saturate` unclamped, FE1's luminance coefficients, pass through for a wrong `values` count); `feConvolveMatrix` (pass through for unmet preconditions, a zero divisor the default, `kernelUnitLength`); `feMorphology` (pass through for a radius that disables it, no 32-bit wrap); `feGaussianBlur` and `feDropShadow` (`stdDeviation` rules); `feComponentTransfer` (the last function element); `feComposite` (`lighter`); sub-regions (`objectBoundingBox` fractions of the box, the inputs' union as the default, every result clipped, a disabled primitive transparent and the chain going on); and the `filter` property (a broken reference applies no filter, a filter with no primitive hides the element, `objectBoundingBox` on an empty box is ignored).
- A PNG with filters can change between releases of aster where a document relies on resvg's departures: a **breaking (output)** change, in the changelog with each behaviour. Vega's output has no filters, so no chart changes (the corpus baselines are byte-identical).
- A future change to the filters asks first what FE1 says, and only then what resvg does. A new divergence is added to `filterDivergences` with its citation and a `TestSpec*` test, never by loosening a parity bound.
- Where FE1 itself is ambiguous (a garbled sentence in §7, the hueRotate example's 0.2127 against its matrix's 0.213, which point of a pixel turbulence samples, how an feImage places an element relative to its sub-region), the reading taken is stated in the code and in api.md, and the evidence for it (another sentence of the specification, or what Chromium or Firefox do, read from their source).
- Some of FE1 is still not drawn, as resvg does not draw it: CSS filter functions, the `BackgroundImage`, `BackgroundAlpha`, `FillPaint` and `StrokePaint` inputs, `feGaussianBlur`'s `edgeMode` and `feBlend`'s `no-composite`. They are features to add, listed in api.md, not divergences this decision covers.
