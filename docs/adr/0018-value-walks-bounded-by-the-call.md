# 0018: Walks of a value are bounded by the call that makes them

**Status:** accepted, 2026-10-19.

## Context

A value built at run time can share its parts. Two expressions, `b1 = [b0, b0, …]` and `b2 = [b1, b1, …]`, hold a few hundred arrays, each charged when it was made, and stand for a tree of 10^8 elements. Everything that visits a value whole walks that tree, as upstream does: `String(v)` (a text mark, a label, an aria description, a group key), `JSON.stringify` (a stack's group key, `VegaLiteToVega`), vega-util's `stringValue`, a deep comparison (an item property's change, `modify()`'s predicate, a scale's padding check), a relational comparison of two arrays (a sort, an extent, a threshold scale), d3's element-by-element interpolation. These walks lived in `jsval` (`AsString`, `AppendJSON`, `StringValue`, `Equal`, `Relate`) and in a few packages of their own, unmetered and uncharged, called from about 550 places. The 2026-10-18 audit (C1, C13) found a 2 KB specification OOM-killed under `WithMemoryLimit(256 MiB)`, a scale domain that ran 20 s past a 2 s timeout, and `Equal` exponential in the depth of sharing. Values nested past `MaxValueDepth` printed `""` in one place and failed in another (C103).

Charging each call site was the fix that kept failing: the property has to hold whichever site walks.

## Decision

- **A walk is made with a `jsval.Walker`**, the call's: `jsval.WalkerFor(ctx)` takes the call's ledger and context. Each value visited is a step of work charged to the ledger, which polls the context, so the deadline ends the walk wherever it is. The text a walk builds is charged to the ledger's bytes before it is allocated, past 512 bytes: for the rest of the call when the walk returns it (`String`, `StringValue`, `Join`; the caller keeps it, as an expression's string budget charges its strings), until the walk ends when the text goes into the caller's buffer or is dropped once compared (`AppendString`, `AppendJSON`, `Relate`). The walks are `Walker.String`, `StringValue`, `Join`, `AppendString`, `AppendJSON`, `Equal`, `Relate`, the prefix forms for messages, and `Walker.Meter` for a walk with rules of its own (JSON.stringify's for dates and cycles in a stack key, d3's interpolation, `modify()`'s comparison), which meters its steps and text the same way. `Walker.Work` and `Walker.Keep` charge what is done over a value outside a walk (each evaluation of an elementwise interpolator rebuilds its arrays).
- **The call's Walker travels with the call's state**: the Vega view and its dataflow, every operator's parameters, the scenegraph (each mark carries it to its items, so a text line, a font or a colour read from an array is walked with it), the SVG writer, every scale (`SetWalker`, kept by `Copy`), the expression scope, the transforms' keys (`transforms.Keys`). Functions that take a `context.Context` derive it there.
- **The forms without a Walker are bounded by fixed caps.** `Value.AsString`, `jsval.Equal`, `Relate`, `StringValue`, `AppendJSON` and the zero Walker visit at most `MaxDetachedWalk` (4,194,304) values and build at most 16 MiB, then stop the call with `ErrLimit`. They are for values whose size the specification's text bounds, a specification's literals read at parse time, and are a backstop for anything else. `Value.String()`, for messages, shows the first KiB.
- **`TestEngineWalksUseTheCallsWalker` enforces it.** In the engine's run-time packages every detached walk must be in a function listed in `scripts/walk.allow`, with the number of walks it makes and why the value cannot be one a run built (a specification literal at parse time, a value whose kind is checked to be no array, a fallback for the package's tests). A new detached walk, a changed count or a stale entry fails. The Vega-Lite compiler, which reads only a specification's literals and meters its own work, and the tools are not scanned.
- **One policy for depth.** A value nested past `MaxValueDepth` (1,024) ends every walk of it with `ErrLimit`, as an expression's string of it does: no walk prints `""`, reports unequal or keeps the end value silently.
- **Identity is a key, not a walk.** `Value.InternKey` is d3's InternMap key (a Date as its time value, -0 as 0, NaN as NaN, an array or object by reference) and `Value.MapKey` a Map's, both comparable in O(1): ordinal domains and `vlSelectionResolve`'s sets are keyed by them (C25, C102), never by a value's text.
- **One string bound.** `jsval.MaxStringLength` (16,777,216 UTF-16 code units) bounds the String of a value as it bounds an expression's strings. Past the call's memory a walk fails with `ErrLimit`, never with V8's `RangeError` (the owner's decision of 2026-10-18).

## Why

The bound is where the walk happens, so no caller can forget it; a caller can only choose the detached form, and the guard makes that choice reviewed. Carrying the Walker beside the state a call already owns (its view, its scene, its scales) keeps the walks' signatures small: no context lookups on the hot path, which a primitive never takes anyway. The identical-reference shortcut of `Equal` makes the common case (a value compared with itself) O(1) however large. Keys by identity make interning O(1) and are upstream's semantics, which the stringified keys were not.

## Consequences

- A chart unchanged: the corpus renders byte-identically (the baseline harness), and the hot paths keep their allocations (a primitive's String or comparison does no walk).
- A hostile shared-reference value now fails with `ErrLimit` or the deadline, within the call's bounds; the bounded-input corpus holds ten such shapes (`testdata/security/bounded/jsval-*`, `log-domain-warning-large`, `ordinal-array-domain-40k`), and the expression library's metering guard calls every function with them, the selection functions over a store of them.
- A detached walk of more than the caps fails where it once succeeded. Nothing in the engine walks a value that large without the call's Walker; a specification literal that large is past any real chart.
- New code that walks a value takes the call's Walker, or explains in `scripts/walk.allow` why it need not.
